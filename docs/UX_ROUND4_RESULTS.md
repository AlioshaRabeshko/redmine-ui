# UX round 4 — результат реалізації

Дата: 2026-10-05. Вимоги: [UX_ROUND4.md](UX_ROUND4.md). Реалізацію й незалежну перевірку виконували Luna max, основний агент інтегрував зміни, переглянув код і скриншоти. Мутаційні перевірки використовували лише demo/mocks; приватний Redmine не змінювали для тестування.

## Реалізована поведінка

- Після перетягування картка відразу відображається в цільовій колонці зі Saving. Старі відповіді polling/SSE не повертають її назад. Однозначна відмова повертає фактичний попередній стан; часткова або невідома помилка звіряється зі свіжим читанням Redmine. Повторного чи компенсаційного запису немає.
- Якщо фактичний стан недоступний, картка показує «Перевірка…» і заблокована від повторного переміщення. Перечитування GET має backoff до 30 секунд. Перевірена недоступність прибирає картку з повідомленням; кешові пропуски не прирівнюються до видалення.
- Дзвіночок має червону заливку та стоїть праворуч від людей у нижньому рядку картки. Кількість, клавіатурний доступ і відкриття конкретної непрочитаної події збережені. Резерв місця не звужує назву чи пріоритет.
- Звичайне відкриття задачі теж читає її фактично переглянуті події: заголовок і початок усіх представлених частин приблизно по секунді в активній вкладці. Події поза viewport, приховані фільтрами чи буфером, не читаються. Inbox, лічильник картки та favicon змінюються після підтвердження локального read API.
- Backlog — окремий список без канбан-колонок і DnD. Є дата створення, останньої активності, точні дати у tooltip, люди/мітки/пріоритет та швидке «У To Do». Збережені фільтри, Priority desc, URL/history, Q/S/копіювання; нова задача з цього екрана отримує Backlog. Довгі назви й мітки переносяться, горизонтального overflow немає.

## Додаткові знахідки рев’ю

Виправлено втрату фокуса після оптимістичного видалення рядка з беклога, зависання перевірки стану без нових SSE-подій та небезпеку перезаписування новішої текстової чернетки ref-мутацією всередині відкладеного React updater. Для останнього додано контрольоване фонове оновлення під час утриманої відповіді збереження; перевіряються новіший текст, доступний Save і повторне відкриття.

Перший повний браузерний прогін: 101/107. Чотири move-перевірки потребували правильного вибору реальної картки замість DragOverlay та прокрутки джерела у viewport; hidden-tab fixture залежав від поведінки headless Chrome; один чинний тест виявив timing-sensitive втрату новішої чернетки. Збережено сутність assertions. Після виправлення move-сценарії пройшли 4/4; hidden-document сценарій перевіряє керовані visibility/focus events, а не native перемикання вкладок ОС.

## Перевірки та runtime

Фінальні build/typecheck та Vitest пройшли: 243/243 у 42 файлах після виправлення чернеток. Повний Playwright на фінальній збірці: 108/108; попередні шість відмов не повторилися. Цільові перевірки: move 4/4, backlog/independent 4/4 після останньої CSS правки, Activity/drafts 6/6. Вісім скриншотів охоплюють board/backlog, light/dark, 1280/1600; основний агент переглянув light backlog і dark board.

Docker оновлено зі збереженням SQLite volume. GET-only smoke на localhost:3010 підтвердив health 200, connected=true, mode=redmine, readOnly=false, canWrite=true та фінальний asset `/assets/index-DH1_m5rG.js` з HTTP 200. Раніше дозволений runtime write mode збережено; реальні мутації для перевірок не виконували.
