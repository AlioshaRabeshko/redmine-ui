# UX round 5 — перевірка legacy E2E

Дата: 2026-10-14

## Покриття

`e2e/ux-revision.spec.ts` містить 17 сценаріїв, що захищають уже наявні потоки дошки та картки під час інтеграції UX round 5:

| Сценарії | Перевірювана поведінка |
| --- | --- |
| Створення й Backlog | Створення з колонки статусу або релізу, збереження текстової чернетки, створення на порожній відфільтрованій дошці та у Backlog. |
| Фільтри й клавіатура | Overlay без зсуву дошки, Q змінює лише фільтр «мої», збережені фільтри, вкладені picker-и та закриття одного шару через Escape. |
| Картка й шорткати | URL і Branch копіюються з фактично сфокусованої картки; S відкриває швидку зміну її статусу. |
| Чернетки й конфлікти | Автозбереження дискретних полів не надсилає опис або коментар; Cmd/Ctrl+S зберігає тільки опис; зовнішня зміна статусу не відкочується; помилка поля та запис під час набору зберігають чернетку. |
| Люди й картки | Успішний вибір людини підвищує її рекомендацію; створення підтримує плитки пріоритету/типу, рекомендовані аватари та пошук повного списку. |
| Автоматизація та налаштування | CI-повернення перевіряється після закриття вкладки; звичайні налаштування зберігаються автоматично, чернетка шорткатів — явною дією; локальні ролі QA очищуються та відновлюються. |
| Релізи й палітри | Помилка створення релізу лишає форму відкритою, очищення дати переживає повторне відкриття; контраст тексту перевіряється у світлій і темній темах для всіх палітр. |

## Виправлення сумісності тестів

- Чернетки опису й коментаря тепер адресуються через спільний RichEditor helper. Для перевірок збережено точний source text; перед редагуванням опису відкривається його preview за замовчуванням.
- Picker виконавців використовує типізовані значення `user:<id>`. Тести вибору та пошуку тепер шукають `user:2` / `user:3`, зберігаючи серверну перевірку `assignedToId`.
- Bootstrap тестів очищає згорнуті колонки явним `null` для кожного проєкту. Порожня мапа є merge-патчем і не знімає збережені згортання.
- QA виправив helper переходу з preview в source mode: він очікує завершення асинхронного завантаження опису перед кліком редагування.

## Фактичні прогони

Перший інтеграційний прогін QA охопив 26 тестів: пройшли 19. Він передував виправленням fixture/helper/selector і не зарахований як фінальна перевірка.

У CI-сценарії первинно задача лишалася в Review з виконавцем 3. Очікуваний результат To Do/виконавець 2/незмінний реліз 100 не послаблювали. Playwright тепер явно задає `Build: Running` та `Build: Failed` лише для isolated demo fixtures, незалежно від локального dotenv-конфігу. `.env` для дослідження тесту не читався; точна роль локального override не заявляється як підтверджений факт.

Фінальний повтор: **26/26**, включно з CI-сценарієм. Повний Chromium: **127/127**, 3 хв 6 с; усі 17 сценаріїв цього файлу увійшли до успішного набору. Команди, screenshot coverage й межі: [UX_ROUND5_QA.md](UX_ROUND5_QA.md).

Цей підагент не запускав сервер, build чи E2E; прогони й контроль порту 3100 виконував окремий QA агент. Фінальні результати додано основним агентом за його звітом.
