# UX round 5 — незалежний QA

Дата: 2026-10-14. Усі браузерні сценарії виконувалися через Playwright проти ізольованого demo app із тестовим SQLite. Реальний Redmine, Trello та production/staging бази не змінювалися.

## Автоматизована перевірка

Фінальний targeted прогін охопив 26 тестів і завершився успішно:

```text
npx playwright test e2e/round4-moves.spec.ts e2e/round5-board.spec.ts e2e/round5-visual.spec.ts e2e/ux-revision.spec.ts --reporter=line
26 passed (35.9s)
```

Він перевірив чотири сценарії optimistic move і відновлення після відмови/невизначеного результату, watcher URL та saved view, ізоляцію налаштувань згорнутих колонок за проєктом, недоступні статуси, призначення на групу з числовою колізією, підписку на нові задачі, старі UX-потоки картки/Backlog/фільтрів/гарячих клавіш/чернеток/налаштувань, а також тему й контраст палітр.

Повний Chromium gate пройшов:

```text
npx playwright test --reporter=line
127 passed (3m 6s)
```

До повного набору увійшли нові редакторські й інтеграційні перевірки. Вони перевіряють справжні pointer/keyboard дії та точний source roundtrip, клік по посиланню у preview, Markdown і Textile збереження невідомих блоків/таблиць/вкладених списків/мови code fence, безпечний paste та HTML preview, mention лише учасників проєкту, зображення й retry, поточного недоступного виконавця, розрізнення user/group, створення задачі з групою, свіжі дозволені переходи статусу та event-specific acknowledgment. Точні сценарії описані в `e2e/round5-editor.spec.ts`, `e2e/round5-integration.spec.ts` і `e2e/round5-board.spec.ts`.

Після повного набору окремо повторено візуальний сценарій на свіжих demo fixtures:

```text
npx playwright test e2e/round5-visual.spec.ts --reporter=line
1 passed (6.8s)
```

Тести зберегли змістовні очікування: зокрема точний текст source, дозволені переходи, результат CI-автоматизації, вміст чернетки під час in-flight save та підтверджений стан після optimistic move. Playwright задає власні CI label values для ізоляції fixture; це не змінює runtime налаштування користувача.

## Візуальна перевірка

Переглянуто пікселі всіх 12 скриншотів після вилучення дубльованого Preview/Edit рядка: ширини 1280 і 1600 px, світла й темна теми, стани дошки зі згорнутою колонкою, опису в preview та візуального редактора. Файли створені тестом `e2e/round5-visual.spec.ts` у `/tmp/round5-{1280,1600}-{light,dark}-{board-collapsed,dialog-preview,dialog-editor}.png`.

На обох розмірах текст і контроли залишаються розбірливими у світлій та темній темах. При 1280 px дошка горизонтально прокручується, тому видно лише частину крайніх колонок; при 1600 px усі колонки вміщуються. Діалог редагування/перегляду в межах viewport, а його вміст прокручується; перевірені стани не показали обрізаних контролів чи накладання елементів. У preview збережене посилання виглядає і поводиться як посилання. У UI більше немає зайвого другого ряду Preview/Edit.

Скриншоти були зняті на demo даних. Вони не перевіряють інші локалізації, браузери чи мобільні ширини.

## Попередній прогін і виправлення

Перший повний Chromium прогін було зупинено за вказівкою координатора, щоб не продовжувати на застарілому demo build після виявлення проблем. На той момент Playwright показав 85 passed, 10 failed, 1 interrupted і 31 not run; це не фінальний результат. Невдачі охоплювали відсутній `allowedStatusIds` у нових demo задачах, некоректне очищення persisted collapsed-column map у fixtures, застарілі редакторські селектори та race з асинхронним завантаженням опису, перехід на типізовані значення picker-а (`user:<id>`) і залежність CI fixture від label overrides середовища.

Після backend/fixture та selector/helper виправлень targeting і повний suite повторно пройшли із зеленим результатом вище. CI Playwright labels тепер задані явно; попередня невдача не доводить, що саме user dotenv був її причиною, бо секретний чи локальний `.env` не читався.

## Межі перевірки

- Мутаційні E2E перевіряють лише demo або mock transports; режим реального запису проти Redmine не тестувався.
- Мобільний UX аудит відкладений за рішенням користувача. Цей звіт підтверджує desktop лише на 1280 і 1600 px.
- Візуальний pixel review зроблено для зазначених 12 screenshot state-ів; це не повна перевірка кожної сторінки, локалізації, браузера чи теми.
- Для CommonMark невідоме приватне налаштування інстансу `common_mark_enable_hardbreaks`; поведінка hard break не заявляється як підтверджена.
