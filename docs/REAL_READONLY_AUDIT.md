# Перевірка інтеграції Redmine у режимі читання

Цей документ містить лише загальні висновки. Ідентифікатори, адреси, назви проєктів і карток, облікові записи, обсяги даних та результати перевірки прав доступу конкретної інсталяції прибрані.

## Висновки

- Redmine може позначати workflow-статус як закритий, хоча продукту потрібно продовжувати показувати цю колонку. Відображення слід визначати за семантикою статусу, а не лише за прапорцем is_closed.
- Labels зберігаються як значення опцій custom field. ID полів та опцій належать інсталяції й проєкту; адаптер має динамічно отримувати каталог і зіставляти ID з назвами.
- Журнали можуть повертати числові значення статусів, виконавців і labels. Для UI їх треба локалізувати за довідниками, залишаючи чесний fallback, якщо значення невідоме.
- Частковий кеш не є повним переліком задач, статусів або релізів. Пошук і відображення не мають робити висновок про відсутність даних лише з неповного snapshot.
- Вкладення показуються через локальний backend route; можливості зовнішнього API та форматування залежать від інсталяції.

## Конфігурація та перевірки

Спільний код не містить адреси Redmine, токена, project/status/custom-field IDs або ID options. Backend бере URL і токен із локального env; людиночитані workflow labels можна налаштувати окремо. Записні сценарії розробки перевіряються лише на ізольованих demo fixtures або mock transport.
