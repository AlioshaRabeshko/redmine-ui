# Issue dialog та спільне компонування — Round 3

`IssueDialog` тепер показує компактний рядок з типом, ID і повною назвою задачі у нерухомому заголовку. Copy/Open actions доступні з меню `⋯`; окремий верхній toolbar і нижній блок Actual status / Close прибрані. Activity filters, count і заголовок стоять на спільній планці, а коментарний composer — перед журналом.

Нові записи Activity залишаються за кнопкою «Показати нові події», доки користувач не застосує оновлення. Уже показані записи оновлюються/видаляються разом із серверним станом; власний щойно відправлений коментар може з'явитися одразу, коли серед нових журналів знайдено запис цього користувача з тим самим текстом і часом. Перевірка виключає ID, відомі до надсилання, щоб збіг із раніше buffered-коментарем не розкривав неправильний запис. Permalink-target примусово лишається видимим і передається як успішно показаний лише після scroll/focus.

Due Date розміщено під Labels, але залишено у явному save-потоці текстової форми через HTML `form` association. Labels замінено на кольорові багатовибірні плитки з активним станом, клавіатурним переміщенням, пошуком для довгого каталогу та показом уже вибраних значень поза каталогом. Для fallback initials колір визначається стабільним ID людини; фото й emoji не перефарбовуються, а role shape лишається окремим сигналом.

Узагальнений `Modal` підтримує необов'язковий заголовок/дії, включає summary в focus order та пропускає приховані елементи закритого меню. Якщо opener зник, повернення фокуса йде до стабільної цілі дошки, або до внутрішнього scroll-панеля іншого екрану. Основна оболонка має viewport-висоту; довгі налаштування скроляться у власній панелі.

`e2e/round3-issue.spec.ts` додає локальні сценарії для sticky-компактного заголовка й меню/focus trap, порядку composer/Activity та computed typography, Due Date + Cmd/Ctrl+S, клавіатурного labels autosave, контрасту avatar в обох темах і scroll-панелі Settings. Довгий Activity для sticky-перевірки синтетично додається у перехоплену відповідь demo API. Інші Round 3 e2e перевіряють buffering при недоступному SSE, draft/scroll збереження та нові події. Перевірки Playwright/build виконуються спільним root gate після готовності всіх source-частин; жодних реальних Redmine/Trello mutations цей код чи ці тести не виконують.
