# UX round 5 — редактор і вміст картки

Дата перевірки: 2026-10-14.

## Реалізація

- Форматтер береться з metadata інстансу (`textFormat`); відсутнє або невідоме значення не вважається Markdown. У такому разі preview показує вихідний текст, а редактор лишається в режимі розмітки.
- Для Markdown/CommonMark візуальний редактор використовує Tiptap. Для Textile він конвертує лише обмежену перевірену підмножину: заголовки, абзаци, прості/розширені цитати, прості вкладені списки, inline bold/italic/strike/code та посилання. Складні/невідомі блоки — таблиці, macros, raw HTML, `bc.`/`pre.`, `<pre>` і розширена цитата `bq..` — у редакторі показуються атомарними збереженими фрагментами; preview відображає `bq..` як quote без зміни source. Markdown reference links/images/footnotes та їхні definition blocks також зберігаються атомарно. Вихідне значення не переписується, поки користувач не змінить візуальний редактор; перемикання в source зберігає початкові фрагменти без конвертації.
- CommonMark preview підтримує обмежений безпечний raw HTML: `rehype-raw` розбирає фрагменти, а `rehype-sanitize` застосовує сувору allowlist Markdown/GFM тегів і дозволених raw HTML елементів. Для raw `code` лишається лише клас `language-*` у форматі Redmine `language-<без пробілів>`; highlighter працює після санітайзера, тільки з явною мовою. `script`, `iframe`, SVG, форми, event-атрибути та небезпечні URL не стають активною розміткою. Raw HTML-зображення проходять той самий issue-scoped resolver, що й Markdown/коментарні зображення; їхні `alt`/`title` зберігаються безпечними атрибутами. Raw `pre`/`code` показує вкладені теги буквальним текстом, але сканер спершу пропускає fenced та inline Markdown code і Redmine macros, тож `<pre>` у прикладі коду не переписує його текст. Макроси, які браузер не може розгорнути, показуються як буквальний code span.
- Code toolbar працює також у Textile: повний Markdown fence від Tiptap конвертується в один `<pre><code class="ruby">…</code></pre>`; explicit language проходить whitelist, plain text не отримує class, а кодові `&`, `<` і `>` екрануються зі збереженням переносів/відступів. У Markdown/CommonMark toolbar лишає fenced code з вибраною мовою. Preview підсвічує тільки явно вказану мову; автоматичне визначення вимкнене.
- Опис спершу показується як preview; клік по вмісту входить у редагування, а кліки на посилання залишаються навігацією.
- Опис і коментарі використовують один issue-scoped маршрут для raster-вкладень. Лише відомі вкладення поточної картки проходять через backend GET; SVG та інші активні/невідомі типи не вбудовуються. Зовнішнє HTTPS-зображення дозволяється напряму без Redmine токена. Помилка зображення має fallback із посиланням на безпечний локальний маршрут і явну кнопку повторного GET; автоматичних повторів немає. Зміна URL/attachment скидає локальний стан помилки.
- Підказка `@` доступна для учасників поточного проєкту, але тільки якщо сервер підтвердив їхній `mentionToken` як фактичний Redmine login. UI вставляє цей точний токен із пробілом; він не генерує синтаксис з імені чи ID і не надсилає окремих mention-сповіщень. IME composition не перехоплює клавіші підказки.
- Призначення зберігає discriminant `user`/`group`, навіть коли числові ID збігаються. Issue detail може надати свіжі `assigneeOptions`; поточне призначення, якого вже немає у списку, лишається видимим як недоступний, але очищуваний вибір. Створення задачі використовує список проєкту.
- Статусний picker показує лише підтверджені per-issue `allowedStatusIds`, разом із поточним статусом. Без підтвердженого списку переходи вимкнені; якщо поточний статус зник із каталогу, він показується окремим недоступним варіантом.
- Конфлікт карткової чернетки очищає тільки subject/description/due date, конфлікт гілки — тільки branch, конфлікт коментаря — тільки чернетку цього journal. Операції блокуються під час відповідного save, тому новіший ввід не стирається підтвердженням старого запиту.
- Редагування/видалення/лайк journal доступні лише за серверними `canEdit`/`canDelete`/`canLike`. Непідтверджена можливість лишається вимкненою.

## Перевірене джерело і межі сумісності

Офіційна [Redmine Textile formatting wiki](https://www.redmine.org/projects/redmine/wiki/RedmineTextFormattingTextile) описує Textile, `bc.`/`pre.` і підсвічування прикладом `<pre><code class="ruby">`. Renderer у [Redmine `application_helper.rb`](https://github.com/redmine/redmine/blob/master/app/helpers/application_helper.rb) використовує `Setting.text_formatting`; отже, загальний default Redmine не є доказом формату конкретного інстансу. Backend безпечним read-only metadata-запитом підтвердив для підключеного інстансу `common_mark`. Точну версію тут не встановлено; `.env` не читався.

Адаптацію CommonMark звірено з офіційним upstream [Redmine `common_mark/formatter.rb`](https://github.com/redmine/redmine/blob/master/lib/redmine/wiki_formatting/common_mark/formatter.rb), [Redmine sanitizer](https://github.com/redmine/redmine/blob/master/lib/redmine/wiki_formatting/common_mark/sanitization_filter.rb) і [remark-gfm](https://github.com/remarkjs/remark-gfm). Preview покриває стандартний CommonMark плюс GFM-таблиці, закреслення, автопосилання, footnotes і task lists через `remark-gfm`. У Redmine upstream також увімкнені tagfilter, alerts і CJK-friendly emphasis. Raw HTML зараз обробляється через [rehype-raw](https://github.com/rehypejs/rehype-raw) і [rehype-sanitize](https://github.com/rehypejs/rehype-sanitize) із вужчим allowlist; це не повна заміна всього Redmine sanitizer. Alert-візуалізація та CJK-specific parsing не реалізовані; їхні можливості також можуть залежати від версії підключеного Redmine.

Redmine upstream вмикає CommonMark hard breaks лише коли `Redmine::Configuration['common_mark_enable_hardbreaks'] == true`; приклад налаштування описаний у [configuration.yml.example](https://github.com/redmine/redmine/blob/master/config/configuration.yml.example). Backend перевірив доступні публічні read-only metadata та не знайшов способу підтвердити це приватне server setting без додаткового непублічного probe. Тому preview залишає стандартну поведінку CommonMark: м’який перенос рядка не стає `<br>` автоматично. Для поточного інстансу hard-break прапорець невідомий; якщо він увімкнений у конфігурації Redmine, preview відрізнятиметься. Upstream [remark-gfm README](https://github.com/remarkjs/remark-gfm) окремо вказує на `remark-breaks` для soft newline → `<br>`; цей плагін тут навмисно не застосовується без підтвердження прапорця.

Redmine документує workflow-per-issue `allowed_statuses` у [REST Issues](https://www.redmine.org/projects/redmine/wiki/Rest_Issues). Для згадок береться лише логін, який backend підтвердив через user API; UI не припускає, що формат `@login` підтримує довільний Redmine/plugin інстанс. Core-поведінка згадок описана в [Redmine issue #13919](https://www.redmine.org/issues/13919?tab=notes), але наявність функції на конкретному інстансі все одно не виводиться з версії навмання.

Візуальна адаптація зберігає невідомі блоки як точні атоми, а не намагається реалізувати весь Textile або кожне upstream CommonMark extension. У Textile навмисно не редагуються візуально макроси, складні таблиці, `notextile`, raw HTML та вже наявні складні кодові блоки. Для CommonMark таблиці, task lists, посилання/зображення у reference-формі та footnote source зберігаються атомами під час зміни сусіднього тексту. Це обмежує інструменти toolbar, але не змінює такі блоки непомітно. Tiptap [Markdown extension](https://tiptap.dev/docs/editor/markdown) позначений постачальником як beta; у цій інтеграції він працює тільки як внутрішній parser/serializer для визначеної підмножини, а source toggle та opaque-node roundtrip є захистом від тихого переписування не підтриманих конструкцій.

- `npx vitest run src/client/components/redmineFormatting.test.ts src/client/components/RichContent.test.tsx` — 27/27; випадки перевіряють Redmine raw `pre/code` з мовою, issue-scoped raw `img` та alt-текст, санітизацію script/frame/event-атрибутів/небезпечних URL, буквальний code-text і макроси, а також точний текст у fenced HTML/inline snippets.
- `npm run typecheck` — пройшов.
- `npm run build` і browser regression після додавання HTML parser/sanitizer тут не запускались: QA володіє активним сервером для E2E, а root виконує фінальний build після інтеграції.
