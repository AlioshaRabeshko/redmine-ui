# Режим запису Redmine

2026-10-05 користувач попросив увімкнути запис. Реальні дії виконуються backend через Redmine REST API з токеном із `.env`; браузер токена не отримує. `REDMINE_WRITE_ENABLED=true` — явне ввімкнення, будь-яке інше значення залишає справжній Redmine лише для читання. Demo залишається ізольованим.

## Команди й межі

- Створення й редагування задач, статус, виконавець, пріоритет, тип, Branch, Labels/Tags та дата завершення.
- Нові коментарі через issue update `notes`.
- Створення, редагування й комплектування Versions; завершення лише через перевірку готовності всіх учасників.
- Review → QA: тимчасово призначити себе, змінити статус, призначити обраного QA. Review/QA → To Do: повернути збереженого розробника.
- Увімкнені фонові автоматизації обробляють нові події CI; історичні readonly операції не повторюються.

Дії залежать від прав користувача, workflow та доступних полів Redmine. Непідтримувані API функції не імітуються змінами локального кешу. Редагування/видалення реальних коментарів і лайки залишаються недоступними до перевірки підтримки конкретної інсталяції. Завантаження нових вкладень не реалізоване.

## Відновлення після помилок

Операція й підтверджені кроки зберігаються у SQLite. Отриманий ID створеної задачі/версії записується до наступних запитів. Повторювати стару readonly операцію як реальний запис заборонено. Втрачена відповідь запису позначається `OUTCOME_UNKNOWN` і не повторюється автоматично.

Браузер зберігає ID незавершеного command intent окремо за інсталяцією та користувачем. Повтор однакового submit, зокрема після reload, використовує той самий ID. У разі відмови localStorage ID утримується лише в поточній вкладці. Змінений payload — інша дія: після невідомого або часткового результату спочатку перевірте задачу й операцію, перш ніж створювати нову дію.

## Перевірки

Автоматизовані мутаційні перевірки виконуються тільки на demo fixtures / mocked HTTP. Smoke підключеного застосунку перевіряє стан і UI тільки GET-запитами; реальні задачі, коментарі або релізи для тесту не змінюються. Підсумкові результати: `npm run build` / typecheck пройшли; Vitest — 221/221 (39 файлів); Chromium Playwright — 95/95, включно з трьома новими write-capability / readonly / reload-retry сценаріями. Окремі mock-регресії покривають частковий QA handoff, збережений ID створення, повтор після branch failure, створення релізу з частковим комплектуванням, невідомий результат коментаря, відновлення CI automation, очищення Labels і заборону обходу завершення релізу.

Локальна `.env` отримала явний opt-in. `docker compose up --build -d --wait` завершився успішно, наявний SQLite volume збережено. GET `/api/bootstrap` та `/api/health` підтвердили `mode=redmine`, `connected=true`, `readOnly=false`, `canWrite=true`; journal editing залишається false. Frontend asset `/assets/index-BbP12V8F.js` доступний (200). `.env` і токен не потрапляють до Git або Docker build context. Реальних мутацій для smoke-перевірки не виконували.
