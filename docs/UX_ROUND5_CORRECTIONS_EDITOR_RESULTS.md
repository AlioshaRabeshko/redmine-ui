# UX round 5 corrections: редактор і форматування

Виправлено два джерела поганого відображення опису й Activity: RichContent тепер скидає успадкований `white-space` до `normal`, а списки в Activity зберігають маркери, вкладеність і звичайне відображення `<li>`. `pre` та код залишають власний режим збереження пробілів. Це охоплює довгу цитату, список, горизонтальну лінію та посилання з наданого прикладу.

У RichEditor додано source-preserving image node для Markdown inline/reference images, Textile `!…!` і дозволених raw HTML `<img>`. Вузол показує фактичне зображення через спільний безпечний issue-scoped resolver, має стани завантаження/помилки та повторну спробу, виділяється й видаляється як один вузол. Форматтер відновлює первісний рядок зображення та посилання reference без зміни атрибутів чи синтаксису при редагуванні сусіднього тексту. Нові вкладення і запис у Redmine тут не додаються. Залежності редактора й sanitizer закріплені точними версіями в `package.json` і lockfile.

Додано браузерні демо-тести для фактичних пікселів і локальних URL вкладень, першої невдалої загрузки з retry, виділення/видалення зображення, точного source round-trip для Markdown і Textile, computed-геометрії цитати/списку/separator та маркерів у реальному Activity DOM. Ці E2E-сценарії написані, але не запускалися за інтеграційним обмеженням root.

Перевірки, які запускалися:

- `npm run typecheck` — успішно, включно з новим e2e-файлом.
- `npx vitest run src/client/components/redmineFormatting.test.ts src/client/components/RichContent.test.tsx` — 2 файли, 30 тестів пройшли.
- `git diff --check` — без зауважень для змінених редакторських файлів до додавання цього звіту.

Browser/E2E, build і сервер не запускалися. Тому фактичне завантаження зображень у Tiptap та computed layout ще чекають інтеграційного E2E gate; наведені вище браузерні перевірки не вважаються пройденими до його виконання.

## Завершений інтеграційний gate

Після первинного unit gate браузерні сценарії підтвердили завантажені зображення, точне source збереження й compact layout. Повтор виявив дефект keyboard Delete: наше перехоплення `mousedown` разом із асинхронним Tiptap focus могло залишити NodeSelection без правильного фокусу. Фінально власний handler прибрано — selectable leaf обробляє ProseMirror із синхронним фокусом. Остаточні 20 зачеплених E2E та три окремі повтори click + Delete пройшли без тестового обходу. PNG-фікстури для image case мають видимий intrinsic розмір 96×64; довга цитата та той самий source у Activity перевірені геометрично й візуально. Деталі: `UX_ROUND5_CORRECTIONS_QA.md`.
