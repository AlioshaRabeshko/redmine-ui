# Незалежний desktop-аудит UI — 2026-10-04

## Середовище та межі

- Ручна перевірка в окремій прихованій вкладці Codex IAB за `http://127.0.0.1:3141`, desktop viewport 1280×720. Піднято з `APP_MODE=demo`, порожнім `REDMINE_API_TOKEN`, `HOST=127.0.0.1`, `PORT=3141` та окремою БД `/tmp/redmine-full-audit-20261004-7f1c4d22.sqlite`. Root підтвердив свіжі `dist` після build/typecheck і unit suite.
- Demo seed має проєкти Core API (10) і Example Project (20), задачі, NEXT/активні релізи, людей, журнали та inbox events. Усі командні дії нижче, якщо будуть, залишаються в цій тимчасовій demo БД.
- Під час першої спроби sandbox заборонив bind localhost (`EPERM`); локальний demo сервер запущений окремим дозволеним процесом. До Redmine/Trello не звертався, зовнішніх мутацій не було; `.env` і token не читався.
- Позначки: **ручне** — фактично перевірено у браузері; **межа** — інструмент не відтворює повний native сценарій. Попередні unit/E2E/build результати не зараховуються як ручне проходження.

## Нові або окремо позначені UX-питання

1. **P3 — пропозиція щодо Inbox, за спостереженням root (підтверджено вручну, не нова самостійна знахідка).** Для групи з однією подією summary показує `Оновлення задачі #issue-example` і preview, але не subject задачі. Щоб перейти до journal, спершу треба розгорнути group, потім натиснути окрему event-кнопку. Expansion сам по собі read state не змінює — очікуваний контракт; P3 не блокує цей раунд.

2. **Виправлений P3 — вибір людини для локальних ролей/аватара губився після reload в одному зі старих проходів.** На Example Project settings до reload picker був з Example Person C і показував блоки ролей/персонального аватара. Один reload того самого URL лишив picker у `Вибрати…`, попри завантажений список; блоки керування були приховані, доки Example Person C не вибрали знову. ⭐ не втратилася. **Кроки:** відкрити Settings → залишити першого користувача → reload → у старій dist побачити placeholder і приховані ролі/аватар. **Очікувано:** після завантаження people list редактор показує валідну людину; **фактично до виправлення:** іноді selection не ініціалізувався. У свіжому build після повного server restart прямий Core API Settings URL одразу показав Example Person C, ролі та ⭐ без ручного вибору; це post-build підтвердження виправлення. Severity P3; на Example Project post-build окремо не ретестовано.

3. **Виправлений P3 — issue modal непослідовно повертав клавіатурний фокус.** Контрольний ручний повтор: відкрив #issue-example через «Відкрити», не переходив Tab-ом (AX focus лишився на «Закрити»), натиснув Escape — URL очистився, active element став WebArea. В іншому проході після Tab до «Копіювати посилання Redmine» Escape повернув фокус на кнопку «Відкрити» картки. **Кроки відтворення:** дошка → issue → «Відкрити» → Escape із початковим фокусом на «Закрити». **Очікувано:** повернутися до opener незалежно від поточного focus point усередині modal; **фактично до виправлення:** WebArea після Escape з «Закрити», але opener після Escape з кнопки копіювання. Baseline Chrome E2E через прогрітий issue cache/lazy chunk і відкладений refresh повторив обидва збої (3 pass / 2 fail із п'яти тестів). У коді додано спільну focus scope для loading→loaded handoff, commit-phase focus capture/initial focus та ізоляцію nested modal; `e2e/modal-focus.spec.ts` покриває холодний delayed handoff, обидва кешовані focus points і повернення після cancel nested confirmation. **Перевірка після виправлення: build/typecheck та всі 5 Chrome regression-тестів пройшли 2026-10-05. Це автоматизований повтор, не заява про новий ручний прогін.** Severity P3: це непослідовно ускладнює клавіатурне продовження роботи; URL і дані не пошкоджуються.

## Обмеження ручної перевірки

- Ручні мутаційні сценарії можна виконувати лише в тимчасовій demo БД; цей запуск не є перевіркою реального write API.
- CUA підтримав semantic click/keyboard та напрямлений horizontal scroll, але не native trackpad inertia/Shift+wheel. Browser/device notifications і фактичні clipboard permission failures не змодельовано.
- Мобільний UX відкладено. Аудит лише IAB desktop viewport; інші браузери, системи та ширини не підтверджені.
- Інші обмеження та частково пройдені сценарії зазначені в таблиці; неперевірене не позначати пройденим. Пост-build перевірка використовувала ту саму тимчасову SQLite, щоб перевірити саме збережений стан після server restart.
