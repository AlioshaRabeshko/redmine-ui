# UX round 2: desktop browser audit

Перевірено 04.10.2026 у desktop-режимі. Реальний preview: `http://127.0.0.1:3010/?project=42` — тільки читання, без зміни налаштувань і без натискання Redmine/Trello write-кнопок. Light theme додатково переглянуто в ізольованому demo на 3131 з окремою SQLite у `/tmp` та порожнім `REDMINE_API_TOKEN`. Токен не читався. Demo процес, вкладку й тимчасову базу прибрано.

Користувач уже попросив природну висоту коротких колонок: довгі мають скролитися в межах viewport, порожні — зберігати usable drop target. |

## Перевірки та межі

- **Horizontal scroll:** `tab.scroll(..., "right", 2)` над лейном і поза ним не показав видимого зсуву. CSS налаштовує горизонтальний scroll дошки та `overscroll-behavior: contain`, а вертикальний scroll лейна працював (`styles.css:118,130-151`). CUA надає лише напрямлений scroll; native trackpad і Shift-wheel ним не перевірені. Тому bounded horizontal behavior — **не підтверджений**, не оголошується дефектом.
- **Light priority:** у demo Urgent/Normal/High мали текстові назви. High amber виглядав блідішим, але жорсткий контрастний дефект не встановлено й числовий WCAG contrast не вимірювався. Chips використовують 11px текст і слабке тло `currentColor 8%` (`styles.css:175-176`).
- Inbox залишено з усіма unread; реальні налаштування не змінювалися. Не перевірялися native trackpad/Shift-wheel, реальні write flows, мобільний UX та автоматизоване вимірювання контрасту.
