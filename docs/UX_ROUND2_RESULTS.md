# Другий UX-раунд: результат інтеграції

## Реалізовані зміни

- Незалежна вертикальна прокрутка колонок, горизонтальне chaining над картками та природна висота коротких і порожніх колонок.
- Виразніші плашки пріоритетів без збільшення компактної типографіки; прибрано верхні дублікати статусу й пріоритету.
- Єдина проєктна проєкція ролей для виконавців, авторів, спостерігачів і учасників активності та Inbox. Виділення аватара узгоджено з формою його рольової рамки.
- Локальні фото й emoji людей із двома Unicode ініціалами як fallback. Персональна іконка діє між проєктами поточного instance/current user; роль залишається проєктною.
- Новіші події першими. Фільтри Activity доступні всередині картки й автоматично зберігаються для всього проєкту.
- Inbox групує події за ID задачі та сортує за останньою подією; відкриття групи не читає її. Читання конкретної події, групи й усіх подій узгоджено з favicon.
- Компактний індикатор тимчасового read-only режиму в заголовку застосунку та відкритої картки.

## Додаткові знахідки незалежного аудиту

Окремо від початкових зауважень виправлено неправдивий індикатор збереження й втрату тексту при відмові localStorage, асинхронну ініціалізацію редактора людини в Settings, повернення фокуса після передачі від завантажувальної до готової модалки та очищення попереднього фото лише після успішного збереження нового. Міграція старих чернеток має зберігати стійку копію до підтвердженого перенесення й не відновлювати вже очищений текст.

Текст при відмові сховища залишається в пам’яті відкритої вкладки; UI чесно попереджає про ризик втрати нових змін після reload або закриття вкладки. Це не гарантія стійкості недоступного браузерного сховища.

## Перевірка

Build/typecheck пройшли. Unit/server — 165 тестів у 27 файлах до фінальної вузької Settings-effect правки; після неї targeted avatar — 1/1 та повний Chrome — 79/79. У першому повному Chrome-прогоні 78/79 було виявлено й виправлено зникнення специфічної помилки заміни фото; assertion залишився незмінним.

## Докладні докази та межі

Docker preview оновлено на http://127.0.0.1:3010/ зі збереженням чинного SQLite volume. Health 200 і новий client asset підтверджені через GET; реальне підключення має mode=redmine, connected=true, readOnly=true, canWrite=false. Відкриту раніше вкладку потрібно перезавантажити.

Мутаційні сценарії виконуються лише в ізольованому demo або mocks. Реальний Redmine залишається GET/HEAD-only; мобільний аудит відкладений. Автоматизований wheel-тест не є повною перевіркою фізичного trackpad; native clipboard permission залежить від браузера й ОС. Незначну UX-пропозицію щодо коротшого відкриття Inbox зафіксовано окремо, без зміни погодженої семантики unread.
