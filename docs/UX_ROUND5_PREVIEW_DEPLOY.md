# Виправлення UX round 5: Preview/Edit і розгортання

## Підготовка до фінальної перевірки

Поточний код містить виправлення відповідності Preview/Edit, білого тла редактора, відступу вкладених списків у 8 px та перенесення довгих рядків коду, узгодженого з режимом редагування. До останньої CSS-зміни пройшли 313 модульних тестів; після неї цільові перевірки пройшли 20/20, а перевірка відповідності Preview/Edit — 1/1. Це цільовий набір, не повторний запуск повного набору модульних тестів. Перегляд PNG підтвердив однакові типографіку й геометрію Preview/Edit на білому тлі. API вподобань для реакцій у Redmine недоступний, тому цей пункт узгоджено позначено як `SKIP`: сервер Redmine не змінюється, зовнішній інтерфейс реакцій не додається, реальних змін у Redmine для перевірки не виконували.

За дозволом батьківського завдання `docker compose build` спочатку зібрав образ із перевіркою Preview/Edit; після останньої CSS-зміни цей образ замінено повторною збіркою нижче. Остання збірка пройшла внутрішні typecheck, Vite та серверну TypeScript-компіляцію. Актуальні клієнтські файли: `index-pbuHlZtS.js`, `IssueDialog-ZRbMZSoh.js` і `RichEditor-D3dDXNnm.js`. Дайджест маніфесту `redmine-ui-app:latest`: `fcddea6b4c40a223b8e2cd8be5ff467c03d4eb29a3fe17237b1330b510810f3b`.

Нативний модуль SQLite перевірили в окремому тимчасовому контейнері з `--network none`, без підключених томів, на базі `:memory:`. `SELECT 1` успішний: `{"binding":"loaded","query":1,"closed":true}`. Збірка вивела попередження Vite про фрагмент коду понад 500 kB та npm про сценарій встановлення `better-sqlite3`; модуль завантажився, npm повідомив про відсутність вразливостей.

## Стан сервісу до фінального gate

Після повторної збірки контейнер `redmine-ui-app-1` не відтворювали: він лишився healthy на попередньому образі `76903ae078d361c5992dc4f3a0b6b542c53d295208e60ccb152daa21f9a406b2`, опублікований лише як `127.0.0.1:3010 -> 3000/tcp`. Актуальна перевірка mount підтвердила `redmine-ui_workspace-data:/data`. Збірка не змінила контейнер чи дані іменованого тому.

До фінального QA gate новий образ не запускали. `.env`, `REDMINE_URL`, токен і прапорець режиму запису не читали й не змінювали. `Config.Env` та розгорнуту конфігурацію Compose не переглядали.

## Після фінального gate

Після дозволу батьківського завдання сервіс буде відтворено командою `docker compose up -d --wait --no-build`. Потрібно зберегти наявний іменований том `redmine-ui_workspace-data:/data` та чинні параметри Compose. Перевірка після запуску обмежується станом контейнера й mount, а також GET-запитами до `/api/health`, `/api/bootstrap`, `/` і головного JS-файла. Для health/bootstrap слід виводити лише HTTP-статус і поля `mode`, `connected`, `readOnly`, `canWrite`; для сторінки — basename asset і його HTTP-статус. Не виводити повні відповіді.

Жодних реальних змін у Redmine для перевірки не виконувати. Якщо health ще не показує з’єднання після старту, дочекатися ініціалізації обмежений час і перевірити знову; не перемикати застосунок у demo.

## Фінальне розгортання

Після зеленого фінального QA gate виконано `docker compose up -d --wait --no-build`. Контейнер запущено на образі з дайджестом маніфесту `fcddea6b4c40a223b8e2cd8be5ff467c03d4eb29a3fe17237b1330b510810f3b`; Docker повідомив стан `healthy`. Порт залишився прив’язаним лише до `127.0.0.1:3010 -> 3000/tcp`. Той самий іменований том `redmine-ui_workspace-data:/data` збережено.

GET-перевірки повернули HTTP 200: `/api/health` і `/api/bootstrap` обидва повідомили `mode=redmine`, `connected=true`, `readOnly=false`, `canWrite=true`. Коренева сторінка `/` повернула HTTP 200, містить посилання на `index-pbuHlZtS.js`, запит цього файла теж повернув HTTP 200.

Виводили лише HTTP-статуси, дозволені метадані, назву JS-файла й дані стану Docker. `.env` та `Config.Env` не читали; жодних змін у Redmine не виконували.
