# UX round 3 — board and live updates

The board now derives both card unread badges and the “With unread notifications” filter from the same unread event list. A badge shows the unread event count and opens the oldest unread event for that issue. The ordinary card opener remains read-neutral. If the selected journal no longer exists in the fetched issue detail, the issue opens without marking the notification read and the user sees a message.

The unread filter is an independent `Filters.hasNotifications` value. It composes with the search, assignment, status, label, priority, release, and closed filters; its `notifications=1` query parameter is parsed and serialized by workspace navigation. Saved filters keep the boolean through server validation. The Q shortcut continues to toggle assigned-to-me while preserving the unread condition and other active filters.

The event stream now invalidates only the selected project board, unread notifications, the exact open issue detail, or the active release that an event affects. Focus and visibility restore those same live reads. If the stream is down or unavailable, board, unread data, and only the currently open issue detail poll every ten seconds. New Activity remains buffered behind its explicit reveal action, leaving an unsent comment draft and the issue scroll position in place.

Opening an unread badge does not read the event just because the issue detail loaded. App keeps a pending read request until IssueDialog confirms that the requested journal is mounted, visible, scrolled into view, and focused (or that a generic issue notification's dialog rendered). A failed board load, a missing target journal, closing or changing the route, and a failed read all leave the event unread. If the badge opener disappears after the final unread event is read, the board exposes a stable modal focus fallback.

Board-only avatar sizing is 30 px for the assigned person and 20 px for secondary people. The styling lives in `board-round3.css` imported by the board feature.

Focused coverage was added in `src/shared/domain.test.ts`, `src/client/lib/workspaceNavigation.test.ts`, `src/client/features/board/unreadNotifications.test.ts`, and `e2e/round3-board.spec.ts`. The browser scenarios cover combined filter/history behavior, saved-filter validation, Q composition, exact event reads only after the target is shown, a board-load failure before the dialog mounts, a card leaving the unread filter while its dialog stays open, focus fallback, board recovery after an unavailable event stream, and active-issue polling with buffered Activity and a preserved draft. These tests are authored for the isolated demo Playwright server and were not run by this subtask; the parent agent is coordinating the validation gate. No Redmine or Trello writes were performed.
