# Повторний аудит UX — 2026-10-04

База початкового аудиту: commit `539f93f`, preview `http://127.0.0.1:3010/`, реальний Redmine лише для читання. Спочатку два Luna max перевірили браузер і код без змін реалізації; основний агент звів висновки й перевірив джерела ролей через read-only GET. Наступним повідомленням користувач дозволив виправлення й повний незалежний desktop-аудит. Опис нижче зберігає початкові докази; актуальний обсяг — RESEARCH.md 19.28 та `UX_FULL_SCENARIOS.md`. Обмеження зовнішніх записів лишається активним.

## Зауваження та нові вимоги користувача

1. Горизонтальний скрол дошки працює лише поза колонками. Горизонтальний жест над картками повинен прокручувати дошку; вертикальний — поточну колонку. Зберегти незалежний вертикальний скрол і DnD autoscroll, уникнути некерованого перехоплення всього wheel.
2. Порожні/короткі колонки не повинні малюватися на всю висоту вікна. Колонка має природну висоту за вмістом із верхньою межею viewport; довгі колонки скроляться. Порожня колонка повинна зберегти заголовок, create button і достатній drop target.
3. Вибраний рекомендований assignee має криву подвійну рамку: круг навколо квадратного рольового аватара. Selection має узгоджуватися з формою role frame, без зміщення/перетину.
4. Новіші події в картці — зверху. Сортування за часом desc, стабільний tie-break; permalink, цитування, редагування коментаря й scroll target мають залишитися коректними.
5. Налаштування Activity має бути доступне безпосередньо в картці, зокрема «лише коментарі». Чинні per-project Activity preferences уже є в Settings, але в картці немає контролю. **Користувач уточнив: вибір із картки зберігається для всіх задач цього проєкту**, через чинні projectActivity preferences та autosave; не transient/per-issue override.
6. Плашки пріоритету на світлій дошці виглядають малоконтрастними. Оцінити окремо контраст тексту, контуру/заливки та розрізнення рівнів. Успішний попередній тест тексту ≥4.5:1 не спростовує зауваження до помітності плашки. Не збільшувати всю типографіку.
7. Прибрати status/priority summary зверху картки: поля вже є справа. Header не має повторювати ті самі дані кількома плашками; roadmap/URL actions можуть зберегти власний зміст.
8. Групувати сповіщення за issue ID. Групи сортувати за останньою подією задачі; усередині — новіші зверху. Зберегти конкретні journal permalinks і незалежний unread кожної події. Відкриття групи не має читати все без явної дії. Фактичний issue.updatedOn як окреме джерело порядку не погоджено.
9. Рамки ролей мають бути у notification actor, авторах і спостерігачах картки. Використовувати ролі відповідного проєкту та локальні overrides, не виводити роль із імені й не переносити роль іншого проєкту.
10. Прибрати великі постійні плашки про тимчасову заборону записів. У topbar показувати compact «Лише читання» з warning icon і поясненням; стан лишається видимим при згорнутому sidebar і відкритій картці. Помилка спроби save має залишитись зрозумілою й не стирати drafts. Заборона зовнішніх мутацій НЕ знімається.
11. Fallback avatar має містити 2 символи навіть для login-style імен без пробілів. Потрібна можливість локально встановити власну картинку/іконку кожної людини для візуального запам'ятовування. Пропозиція: особистий override поточного Redmine instance/user scope, одна картинка людини для всіх проєктів; рольові форми залишаються project-specific. Без upload до Redmine/Trello. Це нова можливість, не наявна API-фотографія.

## Початкові докази коду основного агента

- `styles.css`: `.lane-content` має `overscroll-behavior: contain` по обох осях; `.board-lanes` — align-items:stretch, `.board-lane` — height:100%. Це узгоджується з проблемами скролу й висоти, але конкретні жести перевіряє браузерний агент.
- `.assignee-avatar-option` завжди кругла, selection додає круглий border/box-shadow; внутрішній Avatar developer має квадратну рамку. Причина подвійної геометрії на скриншоті відтворюється з CSS.
- `IssueDialog` має status pill і priority summary у toolbar плюс ті самі поля справа; Activity не має свого filter control.
- `InboxPage` сортує плоский список notification.createdOn desc, не групує issue IDs. Actor Avatar використовує snapshot notification.actor, без явного project-members enrichment у самому компоненті.
- `Avatar` бере перші літери двох слів; для одного login слова повертає один символ. API avatars підтримуються, окремого локального icon override ще немає.
- `IssueDialog` зливає `board.members`, `detail.people`, journal users через Map із last-wins. Plain detail/journal objects перезаписують project roles із board.members. Suggested assignees використовують board.members напряму, тому рамки в них є, хоча для тієї ж людини нижче в author/assignee вони можуть зникати. Watchers рендеряться напряму з detail.watchers без явного project-role enrichment. Це перевірений дефект data precedence, не вимога вигадувати роль.
- Read-only GET локального API: 17 unread events належать 8 задачам, 4 задачі мають кілька подій; жоден notification.actor не має roles. У #issue-example author у board.members має QA, у detail.people ролей немає; всі 4 watchers теж без roles. Жодної події не архівовано під час цієї перевірки. Лічильники — snapshot, не стабільна тестова фікстура.

## Фактична браузерна перевірка

Luna перевірив реальний read-only preview та окремий demo на порту 3131. Підтверджено oldest-first журнал #issue-example (30.09 перед 02.10), відсутність Activity control у картці, плоский Inbox із кількома рядками #issue-example, накладання круглої selection рамки на квадратний avatar і постійні великі read-only notices. У light demo підтверджено однакову висоту порожніх, коротких і довгих колонок; перевірено вигляд плашок Urgent/Normal/High. Нового числового порушення контрастності не встановлено.

Вертикальна прокрутка колонки відтворена. Напрямок `scroll right` через CUA не змінив кадр ані над колонкою, ані поза нею: це **не** доказ нативного trackpad/Shift-wheel сценарію. Зауваження користувача прийняте, осьове containment у CSS визначене; реальний горизонтальний жест над картками треба повторно перевірити після зміни. Власний isolated demo процес агента зупинено, тимчасову вкладку закрито; користувацький preview і непрочитані сповіщення не змінено.

## Підсумок початкового рев’ю та порядок виправлень

Зауваження користувача узгоджувалися з базовою реалізацією. Activity preferences існували, але контролю бракувало в місці роботи з журналом; grouping Inbox і локальні іконки потребували нової реалізації. Наведена черга визначає приймання поточного раунду, а не нову паузу розробки.

| Черга | Обсяг | Критерій приймання |
| --- | --- | --- |
| 1 | Горизонтальний скрол, природна висота колонок | Горизонтальний жест над карткою рухає дошку, вертикальний — колонку; короткі колонки не розтягуються, порожні зберігають drop target; DnD autoscroll працює. |
| 2 | Єдина проєктна проєкція людей та геометрія аватарів | Ролі й explicit local overrides застосовуються до всіх учасників, без втрати при merge; selection відповідає формі рамки; fallback має два символи. |
| 3 | Activity newest-first та фільтр у картці | Вибір «лише коментарі» зберігається для проєкту, інші проєкти не змінюються; journal permalink/reveal й дії коментаря зберігають точний target. |
| 4 | Групи сповіщень | Одна група на issue ID, latest-event ordering; expand не читає події, відкриття події читає тільки її, unread/favicon узгоджені. |
| 5 | Пріоритети, дублікати header і компактний read-only | Пріоритет легко розпізнати в обох темах; editable status/priority справа без верхнього дубля; тимчасовий read-only видимий у topbar і відкритій картці. |
| 6 | Локальні зображення людей | Іконку можна встановити/замінити/скинути; вона переживає reload/restart, ізольована за instance/current user, без зовнішнього upload. |

Додатково кодове рев’ю виявило: локальне перевизначення ролі ігнорується для людини поза `membershipIds`, попри доступність вибору в Settings; його треба врахувати в спільній проєкції людей. Статус у верхній частині IssueDialog дублюється двічі — і в eyebrow, і в toolbar. Read-only topbar перекривається modal backdrop, тому компактний індикатор потрібен також у видимому header відкритої картки. Це уточнення реалізації, нових продуктових відповідей не потребують.

Користувач підтвердив фото й emoji з fallback на ініціали. Реалізовано персональний override між проєктами поточного instance/current user; рольова рамка залишається проєктною. PNG/JPEG/WebP до 2 MiB зберігаються тільки локально; жодного upload до Redmine. Деталі реалізації — TECHNICAL.md, фактичні результати повного аудиту додаються в окремі звіти.

## Стан після реалізації

Шість черг вище реалізовано трьома Luna max із розділеною власністю файлів, інтегровано основним агентом. Незалежні Luna перевірили код, UI в окремому demo та Chrome E2E. Після виправлення чернеток build/typecheck, 165 unit/server та 71 Chrome E2E тест пройшли. Під час продовження 2026-10-05 виправлено focus restore, legacy draft migration та error lifecycle заміни фото. Після останньої Settings-effect правки build/typecheck і повний Chrome 79/79 пройшли; початковий unit/server прогін — 165 тестів у 27 файлах. Докази й межі наведені у зведеному UX_ROUND2_RESULTS.md.

Повний огляд додатково підтвердив дефект чернеток при відмові localStorage: текстова форма заявляла про успішне локальне збереження й губила текст після закриття. Виправлено й перевірено в Chrome: індикатор відповідає фактичному persistence, а fallback зберігає текст у межах відкритої вкладки. Інтерфейс попереджає, що без доступного сховища reload/tab close можуть втратити текст. У Settings також виправлено асинхронну ініціалізацію редактора людини; перезапуск demo на тій самій SQLite зберіг аватар, тему, мову, фон та read/archive.
